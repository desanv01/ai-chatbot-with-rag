## Phase8 live checklist

- [ ] **Two-account Auth:** sign-up/email callback and confirmation, sign-in/out, session refresh, password recovery and redirect behavior. Exercise unauthenticated and expired-session paths; ensure neither account can access the other's workspace.
- [ ] **Schema, grants, RLS and Storage:** validate expected schema/types and migration history; inspect table/column/RPC grants and owner policies. Test both accounts and unauthenticated access, private signed upload/preview access, path/job tampering, expiry and direct vector/readiness mutation rejection. Verify server credentials remain server-only.
- [ ] **Providers:** verify configured model selection, streaming and tools, missing-key gating, cancellation/timeouts and safe errors. Confirm Google metadata enrichment and Voyage document/query embeddings have exactly 1,024 finite values. Test optional providers/search only when configured and authorized.
- [ ] **Bounded small PDFs:** verify upload → parser polling → processing → ready → retrieval, and partial failure → failed/unsearchable. Exercise repeats, conflicting filenames/jobs/paths, concurrent reservations and page work, cancellation, interrupted processing, quota and 25 MiB/150 MiB limits without requiring costly oversized ingestion. Preserve existing objects/vectors on conflict/failure. Record any stranded processing document for deliberate review.
- [ ] **Grounding and citations:** use known-answer fixtures, returned-document identity and cross-account isolation, negative/no-match questions, blank physical pages, tables and unusual filenames. Chat retrieval searches all ready documents owned by the current user; it has no document-subset selector. Verify retrieved text, answers, citation filenames and physical PDF page targets agree. Confirm the total document retrieval context bound under multiple results.
- [ ] **Parser and legacy provenance:** verify the deprecated LlamaParse v1 JSON endpoint works with real fixtures and explicit page numbering preserves blanks. Review legacy vector/page provenance separately; do not infer physical alignment from structural completeness or automatically reindex legacy data.
- [ ] **Deletion and persistence:** verify owner-only document/object/vector deletion and file-manager preview selection state. Reload conversations to verify user, assistant, source and tool parts retain stable identities, ordering and final content. Exercise failed/partial saves and confirm visible failure guidance without duplicate or silently missing parts.
- [ ] **Full end-to-end matrix:** record sanitized expected/actual outcomes for unauthenticated, account A and account B; configured/missing providers; clean/blank/table/unusual-name PDFs; processing/ready/failed/interrupted documents; repeats/conflicts/concurrency; streaming/cancellation/provider failure; reload/save failure/deletion. Include positive and negative paths across browser → route → provider/database → response and attach evidence to the main review.

Processing is request-bound. Failure status is best-effort; cancellation/termination can leave an unsearchable `processing` document. There is no durable background worker, resumable job or automatic model retry. Deliberate deletion and re-upload requires review of the affected document, especially valuable legacy data. See [processing details](V1_PROCESSING.md).

## Troubleshooting

| Symptom | Safe response |
| --- | --- |
| `401` / `403` on upload or processing | Sign in and restart an expired signed upload through the normal flow. Never bypass ownership or job-token guards. |
| `503` for required provider configuration | Check the provider names reported by the error privately; ingestion requires Google, LlamaCloud and Voyage keys. Existing credentials and limited connectivity do not establish the full provider workflow. |
| `409` filename/path/job conflict | The existing document/object is preserved. Choose a new filename, or deliberately review and delete an unfinished record before a fresh upload. |
| `422` PDF/parser page result malformed or unusable | Preserve the source PDF; inspect sanitized page metadata and the deprecated v1 endpoint's compatibility during authorized Phase8 checks. Do not invent page positions. |
| Document remains `processing` or becomes `failed` | It is excluded from retrieval. Check its state and failure guidance; review and back up valuable legacy data before deliberate cleanup. There is no automatic resume. |
| Visible chat save failure or incomplete reload | Reload and assess which user, assistant and tool parts were saved before retrying; do not assume the stream was fully persisted. |
| Migration unique-path conflict | Stop and manually review the conflict against a backup. Never automatically deduplicate, delete records or reset the backend. |
| Migration source/history versions differ | The processing-state mismatch was resolved after normalized SQL equality was verified: only history version `20261013014844` changed to `20261006232436`, with the same name/statements and no schema/data rerun. Inspect any future mismatch before `db push`; do not blindly reapply migrations. |
| Legacy document path has no matching Storage object | Preserve the record and objects for manual review. Do not guess a replacement path or automatically reindex/delete. |
| Confirmation/recovery email does not arrive | SMTP is currently disabled. Configure a sender before testing recipients; temporary inboxes cannot replace sender setup. Default Supabase SMTP permits only project-team recipients ([official guidance](https://supabase.com/docs/guides/auth/auth-smtp)). Optional temporary Gmail SMTP with a private app password was offered for minimal setup; actual delivery remains pending. Check sender settings and allowlisted `/api/auth/confirm` URLs, including recovery `next=/redirect/auth-password-update`. |
| Placeholder build passes, or service behavior still fails | The build fixture proves compilation only. Preserve `.env.local` and the lockfile; use `npm ci` for locked dependency setup. Follow the authorized Phase8 checks to establish service health. Never deploy the fixture. |

Main owns planning, audit, testing, GitHub review and final acceptance. Update this checklist with sanitized live receipts only after the corresponding authorized checks actually run; do not substitute credential presence or a placeholder build for operational evidence.
